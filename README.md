# dsh-kanban

Доска задач для [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness): задачи из Gitea, колонки по реальному воркфлоу и отдельная сессия агента под каждую задачу.

## Что умеет

- **Ставить задачи и следить за ними.** Свои задачи и задачи из Gitea на одной доске, порядок карточек переживает перезагрузку.
- **Заводить задачу из issue.** Кнопка «+ Задача» показывает открытые issue выбранного репозитория; уже импортированные приглушены. Карточка заполняется заголовком, телом, метками и ссылкой.
- **Запускать работу.** Выбрали модель, нажали «Начать» — поднимается отдельная сессия агента по этой задаче, карточка уезжает в «В работе».
- **Показывать задачу в чате.** В сессии, поднятой с доски, в шапке виден чип задачи с текущей колонкой.

## Установка

```bash
dsh plugin --profile web add @goodandready/dsh-kanban
```

Из локальной рабочей копии:

```bash
dsh plugin --profile web add file:/путь/к/dsh-kanban
```

Перезапустите веб-интерфейс и обновите страницу с очисткой кэша.

Импорт задач из Gitea требует установленного `@goodandready/dsh-gitea` с сервисом `gitea`. Без него доска работает, а импорт честно объясняет, чего не хватает.

## Настройка

**Настройки → Плагины**, карточка **Канбан**.

| Поле | Что задаёт |
|---|---|
| Корень проектов | Где лежат рабочие копии. Пусто — рабочая папка харнесса. |
| Шаблон первого сообщения | Текст, с которого начинается сессия. Пусто — встроенный. Подстановки: `{repo}`, `{issueNumber}`, `{title}`, `{body}`, `{issueUrl}`. |
| Метки колонок | Имя метки Gitea для «В работе», «Ревью», «Deploy», «Cleanup». Пусто — метка не ставится. |
| Пределы колонок | Предел числа карточек. Ноль — без предела. |

Токен Gitea здесь **не спрашивается**: доступ берётся из плагина Gitea, где он уже настроен.

Все поля настроек скалярные. Это не упрощение, а требование: клиентский API настроек пишет только скаляры, и словарь или массив сделал бы карточку нередактируемой. Доски поэтому живут в хранилище задач, а не в настройках.

## Колонки

| Колонка | Признак входа |
|---|---|
| Backlog | issue есть, никто не взял |
| В работе | сессия поднята, в issue есть стартовый комментарий с планом и веткой |
| Ревью | PR снят с WIP, ревьюер даёт PASS/FAIL |
| Deploy | PR влит в `main`, ждём согласованный deploy и production-проверку |
| Cleanup | ветка в Gitea, worktree и локальная ветка ещё не удалены |
| Done | issue закрыт **и** cleanup записан в итоговом комментарии |

Колонка `cleanup` не лишняя: по воркфлоу задача не завершена, пока cleanup не сделан и не записан. Доска, отправляющая карточку в `done` по merge, врёт ровно там, где копятся забытые ветки.

WIP PR **не** двигает карточку в «Ревью»: он открывается рано и означает «работа идёт», а не «смотрите».

Превышение предела колонки подсвечивается, но перенос не запрещает: предел — ориентир, а не преграда.

## Чего плагин не делает

- **Не создаёт ветки и worktree.** По воркфлоу агент сначала делает preflight — смотрит открытые ветки и worktree, проверяет рабочее дерево — и только потом заводит worktree от свежего `origin/main`. Ветка, созданная заранее, обессмысливает preflight.
- **Не пишет стартовый комментарий в issue.** Его пишет агент после preflight, потому что до preflight ветка и план неизвестны.
- **Не подсказывает имя ветки** в первом сообщении: его выбирает агент.
- Ветка и worktree на карточке — **наблюдение**, а не намерение.
- Не трогает Hermes Kanban. Это другая система.

## Хранилище

`<DSH_HOME>/kanban/kanban.db`, где `DSH_HOME` — переменная окружения либо `~/.dsh`. SQLite через встроенный `node:sqlite`; внешних зависимостей нет.

Порядок карточек хранится дробным индексом: перетаскивание — всегда один `UPDATE` одной строки, сколько бы карточек ни было в колонке.

## Ограничения 0.1

- Синхронизация односторонняя: Gitea → канбан, при импорте и по кнопке обновления.
- Карточки двигаются вручную. Автоперемещение по событиям сессии и Gitea — это 0.2.
- Двусторонняя синхронизация с вебхуками — 0.3.
- Служба ядра отдаёт только текущую модель по умолчанию, перечня моделей у неё нет, поэтому модель в пусковой полосе задаётся строкой.
