# dsh-kanban

Доска задач для [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness): задачи из Gitea, колонки по реальному воркфлоу и отдельная сессия агента под каждую задачу.

> Версия 0.1 в работе. Сейчас готов каркас: плагин ставится и показывает карточку настроек. Доска, импорт и запуск задач добавляются следующими задачами.

## Установка

```bash
dsh plugin --profile web add @goodandready/dsh-kanban
```

Из локальной рабочей копии:

```bash
dsh plugin --profile web add file:/путь/к/dsh-kanban
```

Перезапустите веб-интерфейс и обновите страницу с очисткой кэша.

## Настройка

Откройте **Настройки → Плагины** и разверните карточку **Канбан**.

| Поле | Что задаёт |
|---|---|
| Корень проектов | Где лежат рабочие копии. Пусто — рабочая папка харнесса. |
| Шаблон первого сообщения | Текст, с которого начинается сессия по задаче. Пусто — встроенный. |
| Метки колонок | Имя метки Gitea для «В работе», «Ревью», «Deploy», «Cleanup». Пусто — метка не ставится. |
| Пределы колонок | Предел числа карточек. Ноль — без предела. |

Токен Gitea здесь **не спрашивается**. Доступ к Gitea плагин берёт из
`@goodandready/dsh-gitea`, где он уже настроен.

Все поля настроек скалярные. Это не упрощение, а требование: клиентский API
настроек пишет только скаляры, и словарь или массив сделал бы карточку
нередактируемой. Доски поэтому живут не в настройках, а в хранилище задач.

## Колонки

| Колонка | Признак входа |
|---|---|
| Backlog | issue есть, никто не взял |
| В работе | сессия поднята, в issue есть стартовый комментарий с планом и веткой |
| Ревью | PR снят с WIP, ревьюер даёт PASS/FAIL |
| Deploy | PR влит в `main`, ждём согласованный deploy и production-проверку |
| Cleanup | ветка в Gitea, worktree и локальная ветка ещё не удалены |
| Done | issue закрыт **и** cleanup записан в итоговом комментарии |

Колонка `cleanup` не лишняя: по воркфлоу задача не завершена, пока cleanup не
сделан и не записан. Доска, отправляющая карточку в `done` по merge, врёт ровно
там, где копятся забытые ветки.

WIP PR **не** двигает карточку в «Ревью»: он открывается рано и означает
«работа идёт», а не «смотрите».

## Чего плагин не делает

- **Не создаёт ветки и worktree.** По воркфлоу агент сначала делает preflight —
  смотрит открытые ветки и worktree, проверяет рабочее дерево — и только потом
  заводит worktree от свежего `origin/main`. Плагин, создающий ветку заранее,
  ломает preflight.
- **Не пишет стартовый комментарий в issue.** Его пишет агент после preflight,
  потому что до preflight ветка и план неизвестны.
- Ветка и worktree на карточке — **наблюдение**, вычитанное из issue и событий
  Gitea, а не намерение, заданное плагином.
- Не трогает Hermes Kanban. Это другая система.

## Разработка

```bash
npm test
```

Тесты идут без харнесса, без сети и без установленных зависимостей: чистая
логика вынесена в модули без импортов, а браузерная половина проверяется через
`node:vm` с заглушкой загрузчика.
